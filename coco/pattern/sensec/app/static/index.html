Production scripts — inspect the real KEK & CEK

HSM KEK (Azure Key Vault Managed HSM) — list key versions and see which is current:

# list all versions of the KEK
az keyvault key list-versions \
  --hsm-name <your-mhsm-name> \
  --name hsm-master-kek \
  --query "[].{version:name,enabled:attributes.enabled,created:attributes.created}" \
  --output table

# show current key version (non-extractable — bytes never leave the HSM)
az keyvault key show \
  --hsm-name <your-mhsm-name> \
  --name hsm-master-kek

CEK — Cache Encryption Key (regular Azure Key Vault secret) — stored in a separate vault because Managed HSM does not support the Secrets API:

# show secret metadata (no value)
az keyvault secret show \
  --vault-name <your-vault-name> \
  --name hsm-dek-cache-key \
  --query "{name:name,enabled:attributes.enabled,created:attributes.created,expires:attributes.expires}"

# provision / rotate the CEK (32 random bytes, base64-encoded)
python scripts/provision_dek_cache_key.py \
  --vault-name <your-vault-name> \
  --secret-name hsm-dek-cache-key

7. Consumer Application Table — payments-svc's own database

This service never stores ciphertext — the calling app does, in its own schema, right next to its ordinary columns. Creating an account here calls /encrypt for the account_number field only; everything else is plain non-sensitive data. Only edek_id, iv_b64, ciphertext_b64, and tag_b64 are persisted for the sensitive column — exactly the four fields a future decrypt needs, nothing more.

Envelope Encryption Architecture

How a request flows from a calling app through authentication, the encryption service, and the HSM — and where the cross-app grant check and audit log sit in that path. This is the same diagram presented at the start of the design review, kept here as a standing reference alongside the live demo.

Structural changes from the original design-review diagram: PlainID / PBAC is now shown as a standalone external shared policy service that both client apps and the HSM service may depend on — a dashed yellow arrow from the Encryption Service to PlainID shows the optional service-side PBAC check. Auditor SPN is now a separate vertical box outside the Azure subscription boundary (red dashed panel, right side) — it accesses Azure Key Vault and the EDEK Store directly across the boundary with read-only permissions, and is not part of the encryption solution itself. The Redis DEK Cache uses versioned keys (dek:{cek_ver}:{edek_id}) so CEK rotation requires no pod restart and causes no MISS storm: each pod polls Azure KV Secrets every 30 s and calls rotate() in-process; old entries remain readable via the prev-CEK fallback until their 60 s TTL expires. The Grants + Rotation box combines cross-app decrypt grants and KEK rotation under separate scopes (grant vs rotate).
