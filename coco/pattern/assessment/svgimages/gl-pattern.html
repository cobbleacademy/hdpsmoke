PBAC Building Blocks

GL Pattern

Composite field-level access resolution combining centralized and localized group membership. Identity is resolved from AND/OR-combined AD groups (and roles), where a localized group/role may map to more than one sensitive field. When a GroupID condition is supplied the engine returns a single PERMIT/DENY decision, and when it is omitted the engine instead returns the allowed action for every sensitive field the combined Identity can reach.

Identity

A user resolved from a combination of centralized and localized AD groups (or roles), joined by AND/OR logic, each up to 50 unique groups.

Asset

A single field requested from a fixed catalog of 40 predefined sensitive fields spanning PII, PHI, PCI, and PFI. A localized group/role may grant more than one field at once.

Action

The allowed action on a field is always one of two values: FULL or PARTIAL.

Condition

An optional GroupID input. When present, its location is compared against the Identity's location.

  • GroupID provided — the engine compares GroupID's location with the Identity's AND/OR-combined location and returns a single PERMIT or DENY decision.
  • GroupID omitted — the engine returns the full list of sensitive fields for the requested Asset, each mapped to the action (FULL or PARTIAL) the combined Identity is allowed; fields contributed together by the same localized group/role are tagged (e.g. GRP-A).
